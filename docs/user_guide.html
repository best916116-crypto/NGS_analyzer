Amplicon Analyzer User Guide

Amplicon Analyzer processes amplicon FASTQ files into QC summaries, reference-aligned mutation calls, heatmap figures, allele spectrum tables, and exportable reports.

1. Quick Start

  1. Open the analyzer.
  2. Paste the full expected PCR amplicon sequence into Reference amplicon sequence.
  3. Select an Assay type: Custom window, Cas / CRISPR, or TALE / TALEN.
  4. Optional: add extra site rows in Additional sites.
  5. Optional: download the setting CSV template, fill it, then import it to configure the reference, assay, target window, and sample range automatically.
  6. Add FASTQ, FASTQ.GZ, joined FASTQ text files, or choose a folder.
  7. Optional: set a first/last sample number to process only numbered sample groups. Keep Expected sample count at 96 for 96-well batches.
  8. Optional: choose an Expected base edit such as C>T or A>G.
  9. Click Run analysis.
  10. Review QC, the heatmap, the processed table, and the allele spectrum.
  11. Export CSV, summary JSON, SVG, PNG, Markdown, or self-contained HTML report files.

Use Load demo data for a small synthetic run, or Load public benchmark to reproduce the CRISPResso2 EMX1 FASTQ fixture in the app.

2. Inputs

InputDescription
.fastq, .fqPlain FASTQ files.
.fastq.gz, .fq.gzGzip-compressed FASTQ files in browsers that support DecompressionStream.
.fastjoin, .fastqjoin, .fqjoin, .join, .txtJoined or concatenated FASTQ text files.
Setting CSVOptional Amplicon Analyzer template CSV, or legacy CSV with arg, opts, and run_align_mutations rows.
Reference ampliconThe full expected PCR amplicon sequence, using A/C/G/T/N bases.

The file picker accepts individual files. The folder picker accepts a directory of many FASTQ-like files through browser-local file access.

Illumina-style names such as 97_S97_L001_R1_001.fastq.gz are normalized to sample 97, matching joined files such as 97.fastqjoin. If joined and raw R1/R2 files are loaded for the same sample, joined files are used and raw files are skipped to avoid double counting.

R1/R2 files are grouped by inferred sample name. If raw R1/R2 FASTQ files are supplied without joined FASTQ files, R2 is reverse-complemented and high-confidence overlaps are converted into consensus reads before QC and alignment.

Reference is the full alignment target. Targeting window is the smaller region within the reference that is highlighted in the heatmap.

The downloadable setting template uses one row per amplicon site:

site_name,reference_amplicon_sequence,target_positions,assay_type,spacer_sequence,pam_sequence,spacer_window,tale_left_sequence,tale_right_sequence,tale_spacer_sequence,tale_padding,expected_edit,sample_start,sample_end,expected_sample_count,preferred_input,notes

Only filled fields are used. assay_type overrides inference. If it is blank, pam_sequence infers Cas / CRISPR, with spacer_sequence required for guide mapping; TALE binding sites or spacer-only rows infer TALE / TALEN; target_positions alone uses custom mode.

3. Multi-Site Analysis

Use the primary reference fields for the first site. Add optional extra sites as one row per amplicon:

site_name, reference_amplicon_sequence, target_positions
site_B, ACGTACGT..., 16-23
site_C, ACGTACGT..., 12,18,22

FASTQ files are parsed and QC-filtered once per sample group, then each site reference is aligned and summarized separately. The heatmap displays one selected site at a time. CSV and report exports include all analyzed sites.

4. Assay Type and Targeting Window

ModeHow the targeting window is determined
Custom windowUses the manual 1-based target positions entered in the app.
Cas / CRISPRFinds the spacer/guide sequence in the reference, checks the PAM pattern when possible, then maps the spacer window to amplicon coordinates.
TALE / TALENFinds left and right TALE binding sites and uses the intervening spacer as the default targeting window.

For TALE/TALEN assays, left/right binding sites are more reliable than spacer-only input because they define orientation and the intervening region.

6. 96-Sample Batch Runs

For routine 96-sample batches, import the setting CSV, choose the fastqjoin or FASTQ.GZ folder, and confirm that preflight reports 96 selected sample groups. Raw FASTQ.GZ R1/R2 files are joined automatically when a high-confidence overlap is found.

Legacy setting CSV import maps --user_region_beg_offset and --user_region_length to 1-based amplicon target positions. For example, if the site starts at position 61, --user_region_beg_offset 32 --user_region_length 55 becomes target positions 29-83.

7. Results

  • Overview: site summary, sample-level QC-passed reads, alignment-passed reads, unique reads, mean Q, mean identity, max edit rate, and target source.
  • Sortable overview: click sample table headers to toggle ascending and descending order.
  • Expected edit summary: target-window expected conversion rate when a base-edit model is selected.
  • QC: filtering counts, low-identity read counts, paired-end join counts, malformed records, and read-limit status.
  • Processed table: position-level substitution, deletion, insertion, signal reads, and edit percentage.
  • Allele spectrum: unique read sequences with counts, ratios, orientation, identity, and edit signatures.
  • Samples: editable sample labels for figures and exports.

The heatmap toolbar supports zoom in/out, fit, reset to 100%, drag-to-pan, Ctrl+wheel zoom, full-figure export, and visible viewport PNG export.

9. Calculation

For each sample and position, edit percentage is calculated as:

edit percentage = selected signal reads at position / position-level covered reads * 100

Coordinates are 1-based amplicon positions. The heatmap uses a black grid for amplicon bases, red outlines and labels for target positions, and a reference sequence row below the figure. Terminal no-coverage gaps are not counted as deletion edits.

When an expected base edit is selected, expected edit percentage is calculated only across editable target-window bases. For example, C>T uses target positions where the reference base is C.

11. Paired-End Validation

The repository includes a synthetic paired-end truth test:

node tools/validate-paired-end.mjs

The test creates raw R1/R2 FASTQ files and a matching joined FASTQ fixture, runs both paths through the analyzer, and checks joined read count, aligned read count, expected edit position, and edit percentage.

12. Current Scope

  • FASTQ parsing, paired-end overlap consensus, QC, unique-read aggregation, reference alignment, and mutation calling are performed in the app.
  • Paired-end QC exports include paired reads, joined pairs, unjoined pairs, and unpaired reads.
  • Adapter trimming is not performed; trim adapters upstream when needed.
  • Very large FASTQ files are constrained by local browser memory and CPU.

For production-scale primary analysis, use Amplicon Analyzer as a fast review/export layer and validate final calls against an established command-line workflow.
